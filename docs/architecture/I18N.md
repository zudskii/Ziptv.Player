# Translations (ka / en / ru)

`@ziptv/i18n` (packages/i18n) is the runtime shared by the web client and the operator console.

- **Messages** are ICU MessageFormat (`intl-messageformat`): `{name}`, `{n, number}`,
  `{count, plural, one {# channel} other {# channels}}`, `<b>…</b>` tags for rich parts.
  Russian needs `one / few / many / other`; Georgian nouns do not change after numbers
  (`{count} არხი`), so its messages usually have no plural at all.
- **Catalogs**: `apps/<app>/src/i18n/locales/en.ts` is the source (bundled, `as const`);
  `ka.ts` and `ru.ts` are typed `Catalog<AppMessages>` and loaded on demand. A key missing from, or
  extra in, a translation is a compile error.
- **Use**: `t('nav.home')` anywhere (toasts, helpers), `useT()` in components that must re-render on
  a language change, `tx('key', { b: (chunks) => <b>{chunks}</b> })` for messages with JSX parts.
  The app root subscribes, so a language switch re-renders the whole tree. Never translate at module
  level: a constant built at import time keeps the language it was built in — keep keys in constants
  and call `t` when rendering (or use getters).
- **Language**: device (last choice in localStorage, else `navigator.languages`) → the profile's
  `general.language` wins once settings load (`''` = the device's). The console keeps its language
  per device.
- **Server**: API errors keep English text plus a stable `code`; ka/ru show `errors.code.<CODE>`.
  Emails use the request's `Accept-Language` (the client sends its UI language).
- **Checks** (`src/i18n/*.test.ts` in each app): same keys, valid ICU in every language, the same
  values shown in every language, no Latin-only Georgian, and no hardcoded JSX text
  (`findHardcodedText` from `@ziptv/i18n/lint`).

Adding text: add the key to `en.ts`, `ka.ts` and `ru.ts` (the compiler lists what is missing), then
use it. Numbers in messages: `{n, number}` so they are grouped per language.
